Device & profile

Wi-Fi

The ESP32 radio scans 2.4 GHz only, so 5 GHz-only SSIDs never appear. Changing Wi-Fi, hostname or login reboots the controller. With no Wi-Fi it starts an access point named after the device ID (e.g. ESP32-B03FD3) with your admin login password (default farm1234) — look for that name in your Wi-Fi list.

Remote server (open CoAP)

The ESP32 always calls out to the server. The server never connects in. Until an admin confirms the device, the server returns “waiting for confirmation”.

Live peer-to-peer (WebRTC)

The browser opens an encrypted data channel straight to the controller and pulls the dashboard over it. The server only relays SDP/ICE and is notified of the link state; it cannot read the traffic. STUN and TURN are discovered from the control plane when the overrides are blank; TURN is the fallback when a direct path is blocked. Falls back to HTTP when off.

Pump protection

Hardware self test

Checks the ESP32, RTC, power rail, radio, GPIO driver map, every relay coil, pump contactor, current sensor and float inputs. Relay outputs are pulsed briefly and released.

Time & maintenance

Time is interpreted as device local time (IST-5:30 = UTC+05:30), not browser time.
A DS3231 keeps time through power cuts. NTP corrects it when Wi-Fi is available.

Profiles & pin mapping

Customise an ESP32-WROOM-32 (38-pin DevKit V1) installation: choose how many relays this profile needs (new profiles start with one), map each relay and the pump contactor to a GPIO, then set the daily ON/OFF window and momentary pulse timings. The dashboard only shows the relays defined by the active profile. For a motor with a contactor and START/STOP push buttons, enable "pulse" and enter a second GPIO: the ON time pulses START for the configured milliseconds, the OFF time pulses STOP for its configured milliseconds, then both coils release. A motor without a contactor uses one GPIO that stays on for the window. GPIO 34–39 are input-only; 4 and 5 are used by the RTC. Duplicate GPIOs are rejected.
